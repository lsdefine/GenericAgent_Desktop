# GenericAgent Desktop

Standalone React + Tauri desktop application for [GenericAgent](https://github.com/lsdefine/GenericAgent).

## Development

Requires Node.js 20+, Rust and the platform's Tauri build prerequisites.

```sh
npm install
npm run tauri dev
```

Configure a Python executable and a **separate GenericAgent project directory** in the desktop startup settings. The repositories may live anywhere; Desktop does not search its parent directories for GA. Python dependencies belong to the selected GA environment.

```sh
npm test
npx tsc --noEmit
npm run build
npm run test:bundle
npm run test:packaging
```

## Ownership

- `src/`, `public/`: React UI and desktop web assets.
- `src-tauri/`: native shell and GA process lifecycle.
- `scripts/ga_contract_probe.py`: desktop compatibility check, embedded into the shell at build time; accepts the target GA path explicitly.
- `packaging/`, `.github/workflows/`: installers and release assembly.
- `tests/`, `testing/`, `docs/`, `spec/`: integration checks and desktop documentation.
- GA owns `agentmain.py`, LLM execution, `frontends/desktop_bridge.py`, conductor and usage persistence. Fix backend behavior in the GA repository, not by copying it here.

## Releases

Run **Build Desktop components and Windows source releases** manually (select a platform), or push a `desktop-component-*` tag. By default CI builds the shell with its embedded UI. Manual Windows builds can additionally enable `windows_release` and select `ga_ref` to assemble and verify both source-layout packages.

- Windows x64: `GenericAgent.exe`.
- macOS Apple Silicon: `GenericAgent-Desktop-macOS-arm64.zip`, containing `GenericAgent.app`. CI ad-hoc signs the app and verifies its signature again after extraction. This is not Developer ID signing or notarization; Intel is not currently built.
- Linux x64: `GenericAgent-Linux-x86_64.AppImage`.

Each Actions artifact includes SHA256 checksums and a manifest with the Desktop commit and target. Private Actions artifacts require authentication and expire after 30 days. For distribution, publish the component and its checksum to the existing public binary distribution channel; this workflow does not publish automatically.

CI belongs only to this Desktop repository; GA has no CI or assembly workflow. Download the component, verify its SHA256, and place it directly in GA's `frontends/` (not `frontends/desktop/`). Windows publication continues through the existing release procedure. Windows source and self-contained packages share the same GA source root and `frontends/GenericAgent.exe`. The self-contained ZIP only adds `python/` with preinstalled dependencies. There is no `runtime/app` nesting or first-run dependency installation. Saved `project_dir` and `python_path` take precedence independently, including in packaged builds. Only unset fields are discovered. Project discovery checks up to eight levels from the executable anchor, then the launcher working directory, validating both `agentmain.py` and `frontends/desktop_bridge.py`. It supports root/frontends/development-build locations, a `GenericAgent/` wrapper, and legacy `runtime/app` including macOS Resources. Python discovery stays with the selected project: `.venv/`, `venv/`, `python/`, `runtime/python/`, or legacy sibling `runtime/python/`, then system Python. It never recursively scans disks or picks arbitrary sibling repositories. Non-empty invalid settings are not silently replaced. `ga_source_override` retains its existing explicit external-core behavior. Old `runtime/app` bundles remain readable for compatibility.

`dist/` is generated by Vite and embedded by Tauri. No static files are copied into GA. No GA checkout, build cache or local regression-test additions should be committed here.

### Windows source-layout artifacts

- `GenericAgent-Windows-Source.zip`: committed GA source + `frontends/GenericAgent.exe` + launcher.
- `GenericAgent-Windows-WithPython.zip`: byte-identical common files, plus `python/`.
- Extract the whole directory to a writable location. Open `Start GenericAgent.cmd`.
- WebView2 remains a system prerequisite. Never overwrite user config/history during upgrades.
- `scripts/package_windows.py` assembles clean Git source, not a developer working tree.
- `scripts/prepare_windows_python.py` prepares pinned standalone Python, UCRT, and locked dependencies.
- `scripts/verify_windows_release.py` compares both ZIPs byte-for-byte and tests the relocated packaged bridge on an isolated port. This is not desktop GUI acceptance.
- The workflow uploads Actions artifacts only; public release publication remains explicit.
